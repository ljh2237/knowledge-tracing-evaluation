# 知识追踪模型评价指标说明

负责人 B 刘静涵 / 交付版本 **1.0.0**。

本文档说明本项目为什么选择这些指标、每个指标的精确定义与计算方法、适用条件与局限，
以及计算时的统一口径。对应的程序实现在 `evaluation/evaluator.py`。

## 1. 指标体系总览

| 指标 | 符号 | 方向 | 随机基线 | 主要回答的问题 |
| --- | --- | --- | --- | --- |
| ROC-AUC | AUC | 越大越好 | 0.5 | 模型能否把「会答对」和「会答错」的学生-题目组合**排序**开 |
| Accuracy | ACC | 越大越好 | 多数类占比 | 在给定阈值下，**二分类判断**有多少是对的 |
| Log Loss | LL | 越小越好 | 由标签分布决定 | 模型给出的**概率本身**准不准（是否过度自信） |
| Brier 分数 | BS | 越小越好 | 由标签分布决定 | 概率预测的**均方误差**，对极端错误更敏感 |

四个指标在 `metrics/metrics.csv` 中全部输出，报告中以 AUC、Accuracy、Log Loss 为主。

## 2. 为什么选这四个指标

### 2.1 为什么必须有 AUC

知识追踪的核心任务是**预测下一次作答是否正确**，且输出是概率。AUC 衡量的是
「随机抽一个真实答对的样本和一个真实答错的样本，模型给前者更高概率的可能性」，
它：

- **不需要选阈值**，因此不受人为设定 0.5 的影响，适合作为模型间对比的主指标；
- 对类别不平衡稳健——知识追踪数据里答对比例常在 0.6–0.8 之间，
  单纯看 Accuracy 会被多数类主导；
- 与知识追踪文献（DKT、AKT 及其变体）的通行报告口径一致，便于横向比较。

### 2.2 为什么还要 Accuracy

AUC 只看排序，不看绝对水平。下游的个性化学习路径生成需要**做决策**
（例如「预测正确率低于某阈值就推送该知识点的练习题」），这时必须有一个
明确的分类结果。Accuracy 就是在这个决策口径下的正确率，因此必须与阈值一起报告。

### 2.3 为什么必须有 Log Loss

AUC 与 Accuracy 都对**概率校准**不敏感：把预测概率从 `[0.1, 0.9]` 压成 `[0.45, 0.55]`，
排序不变、分类结果不变，但模型已经变得几乎无信息量。Log Loss 直接惩罚
「给确定会发生的答案很低的概率」，因此能暴露过度自信或校准失败。
对于要用概率做学习路径推荐的系统，这一点尤其重要。

### 2.4 为什么补充 Brier 分数

Brier 是概率预测的均方误差，与 Log Loss 互补：Log Loss 对接近 0/1 的
错误预测惩罚极重（对数发散），Brier 有界于 `[0,1]`，两者一起看可以判断
误差是集中在少数极端样本还是普遍存在。Brier 作为补充参考列出，不作为主指标。

### 2.5 为什么不用 RMSE / MAE / R²

这些是回归指标。本任务的预测目标是 0/1 的答题结果，用回归指标会隐含
「答对 1 比答对 0 好一倍」这类不存在于原始问题中的距离假设，
且无法与知识追踪文献的结论对齐，因此不采用。

## 3. 精确定义与计算方法

记测试集有 `N` 个样本，第 `i` 个样本的真实标签为 `y_i ∈ {0,1}`，
模型输出的答对概率为 `p_i ∈ [0,1]`，正样本数 `P`、负样本数 `Nneg`。

### 3.1 ROC-AUC

定义：随机取一对「一正一负」样本，正样本得分严格高于负样本的概率，
得分相同时计 0.5（Mann-Whitney U 统计量）。

```text
AUC = ( Σ_{i: y_i=1} Σ_{j: y_j=0} [ 1  if p_i > p_j
                                    0.5 if p_i = p_j
                                    0   if p_i < p_j ] ) / (P · Nneg)
```

实现：`sklearn.metrics.roc_auc_score(y_true, y_pred)`。

**并列处理**：项目自带的常量插件 `example_constant_plugin` 对所有样本输出 0.6，
按定义 AUC 恰为 **0.5**（全部并列），实际运行结果与之相符——这是验证实现正确性的
一个好用例。

### 3.2 Accuracy

```text
ŷ_i = 1 if p_i ≥ threshold else 0
ACC = (1/N) Σ_i [ ŷ_i = y_i ]
```

实现：`sklearn.metrics.accuracy_score`。默认 `threshold = 0.5`，
可通过 `python evaluate.py metrics --threshold <值>` 修改。

**阈值只影响 Accuracy**，不影响 AUC 与 Log Loss——后两者对全部阈值恒定，
这一点在 `tests/test_evaluator.py` 中有专门用例固定。

### 3.3 Log Loss（二元交叉熵）

```text
LL = -(1/N) Σ_i [ y_i · ln p_i + (1 - y_i) · ln(1 - p_i) ]
```

实现：`sklearn.metrics.log_loss(y_true, y_pred, labels=[0, 1])`。

两点实现细节：

1. **概率裁剪**：`ln 0 = -∞`，因此 scikit-learn 把 `p_i` 裁剪到
   `[ε, 1-ε]`，其中 `ε` 为 `float64` 的机器精度（约 2.22e-16）。
   本项目在验收脚本中用手工实现复现了同一口径，两条路径结果一致到 1e-9。
2. **显式传入 `labels=[0, 1]`**：这样即使测试集只含单一类别，
   Log Loss 仍有定义，不会因为标签种类不足而报错。

### 3.4 Brier 分数

```text
BS = (1/N) Σ_i (p_i - y_i)²
```

按定义直接计算，不依赖 scikit-learn，避免版本差异。

## 4. 统一计算口径

以下口径在全部模块（指标、对比、报告、图表）中完全一致：

1. **AUC 与 Log Loss 一律使用 `y_pred`**（答对概率），
   **绝不使用 `predicted_label`**（0/1 标签）。
2. **`y_pred` 是「当前目标题答对的预测概率」，不是知识掌握概率。**
   项目不允许把两者等同；报告中所有措辞都保持这一区分。
3. **`y_true` 是当前目标题的真实答题结果**，由负责人 A 在模型推理之后关联，
   模型推理时不可见。
4. **样本一次都不丢**：指标在加载时已经通过严格校验（唯一 `record_id`、
   `y_true ∈ {0,1}`、`y_pred ∈ [0,1]` 有限），不存在需要丢弃或插补的样本。
5. **不进任何平滑、不裁剪概率、不换默认值**。

## 5. 单一类别（AUC 不可计算）

当测试集只包含正样本或只包含负样本时，`(P · Nneg) = 0`，AUC 无定义。

本项目的处理：**明确标记为不可计算，并记录原因**，绝不返回 0.5、1.0 或其他占位值。

```json
{
  "roc_auc": null,
  "auc_status": "undefined_single_class",
  "auc_reason": "测试集只包含正样本（正样本 12 条、负样本 0 条），ROC-AUC 无定义，不编造数值"
}
```

`auc_status` 的三种取值：

| 取值 | 含义 |
| --- | --- |
| `computed` | 正常算出数值 |
| `undefined_single_class` | 单一类别，理论上无定义 |
| `unavailable` | scikit-learn 因其他原因无法计算（附原始错误信息） |

同组的 Accuracy、Log Loss、Brier **仍然正常计算**——AUC 无定义不代表整组不可评估。
图表遇到不可计算的模型会跳过该模型并在图上标注，而不是画一根 0 或 1 的柱子。

## 6. 冷启动样本的处理

冷启动样本（`history_length = 0`，模型只看到目标题目本身）在真实系统中必然存在，
且通常更难预测。混在一起算会掩盖问题，因此输出三个分组：

| 分组 | 含义 | 用途 |
| --- | --- | --- |
| `all` | 全部有效样本 | 主结果；`--exclude-cold-start` 时可只保留非冷启动 |
| `non_cold_start` | 有可见历史的样本 | 观察模型在有历史时的真实能力 |
| `cold_start` | 无可见历史的样本 | 观察先验/冷启动策略是否合理 |

冷启动样本数可能很少（本项目合成数据中为 12/288），此时其 AUC 单独列出且可能不可计算。
**正式评估必须固定同一套筛选规则**，不能一次含冷启动、一次不含冷启动后互相比较。

## 7. 指标解释的注意事项

1. **AUC 高不等于概率好用**：AUC 只看排序，用概率做推荐时必须同时看 Log Loss。
2. **Accuracy 依赖阈值**：不同阈值下的 Accuracy 不可直接比较，
   报告时必须写明阈值（本项目默认 0.5 并在每行结果中冗余记录）。
3. **类别不平衡时 Accuracy 会误导**：若 80% 样本答对，全预测为「答对」就能得 0.8。
   本项目始终同时报告正负样本数，便于判断基线水平。
4. **模拟数据上的指标没有模型意义**：`is_mock=True` 时，上表数字只反映
   「评估程序是否正确」，不能推断任何 DKT/AKT 的真实精度。
5. **单一指标不能替代对照实验**：模型优劣必须在**同一测试集划分**上比较，
   这正是 `evaluation/model_compare.py` 强制样本严格对齐的原因。
